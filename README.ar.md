# ctxguard

هوك صغير لـ Claude Code يمنع الجلسات الطويلة من استنزاف حدود الاستخدام بصمت. كل رد يعيد قراءة السياق كله، فجلسة بحجم 300 ألف توكن تكلّف أكثر بكثير لكل رسالة من جلسة جديدة. ctxguard يقيس حجم السياق الحالي وعمر الجلسة من سجل المحادثة وينبّه Claude (وإياك) إلى إنهاء الخطوة والتسليم لجلسة جديدة.

- بايثون بالمكتبة القياسية فقط، بلا نموذج ولا شبكة ولا اعتماديات.
- ما يعطّل جلستك أبداً: أي خطأ يطبع لا شيء وينتهي بالرمز 0.
- يعمل على ويندوز ولينكس وماك (بايثون 3.8 فما فوق؛ الأقدم ينتهي بصمت).

## التثبيت

أضف البلجن من الماركت بليس أو حمّله محلياً:

```
claude --plugin-dir /path/to/ctxguard
```

يسجّل البلجن هوكين (`UserPromptSubmit` و`PostToolUse`) يشغّلان `scripts/ctxguard.py`. يحتاج `python3` أو `python` في PATH (بهذا الترتيب، بوضع UTF-8). لا يعتمد أي أدوات مسبقاً ولا يطلب صلاحيات.

## السلوك

| المستوى | الشرط (الافتراضي) | ما يحدث |
|---|---|---|
| خفيف | سياق >= 150 ألف توكن أو عمر >= 6 ساعات | يُضاف تذكير: أنهِ الخطوة، اختصر، احفظ الملاحظات، واقترح جلسة جديدة. |
| قوي | سياق >= 250 ألف توكن أو عمر >= 9 ساعات (العمر وحده يحتاج سياق >= 30 ألف) | تعليمة أقوى: لا وكلاء ولا Workflow جديد، أنهِ الخطوة وسلّم. |
| حجب (اختياري) | سياق >= 500 ألف توكن والحجب مفعّل منك (انظر الإعداد) | تُحجب الرسالة برسالة توضيحية إلا إذا وُجد ملف التجاوز. |

في `UserPromptSubmit` يُضاف التذكير لكل رسالة. في `PostToolUse` يتكرر فقط بعد نمو السياق 25 ألف توكن أو مرور 30 دقيقة. الحجب يحصل فقط في `UserPromptSubmit` وهو مطفأ افتراضياً.

## الإعداد

ملفان اختياريان بنفس المفاتيح (كلها اختيارية): ملف المستخدم `~/.claude/ctxguard.json` وملف المشروع `<project>/.claude/ctxguard.json`. الأولوية: الافتراضيات، ثم ملف المستخدم، ثم ملف المشروع، ثم متغيرات البيئة.

```json
{
  "soft": 150000,
  "strong": 250000,
  "block": 500000,
  "age_soft_h": 6,
  "age_strong_h": 9,
  "block_enabled": false
}
```

- القيم أرقام موجبة (النص والقيم المنطقية مرفوضة). الحدود الدنيا: soft وstrong >= 20000، وblock >= 100000، والأعمار >= 0.5 ساعة. الترتيب صارم: soft < strong < block و age_soft_h < age_strong_h. أي ملف يخالف قاعدة يُتجاهل كله.
- **الحجب اختياري ولا يفعّله إلا المستخدم**: متغير البيئة `CTXGUARD_BLOCK=1` أو `"block_enabled": true` في ملف المستخدم `~/.claude/ctxguard.json`. أي `block_enabled` في ملف المشروع يُتجاهل، فمشروع منسوخ ما يقدر يقفل جلساتك.
- مجلد المشروع هو `CLAUDE_PROJECT_DIR` إن وُجد، وإلا المجلد الحالي للهوك.
- للاستمرار في جلسة محجوبة رغم ذلك: أنشئ ملفاً فارغاً `.claude/ctxguard.override` في المشروع. يسري 12 ساعة (بحسب وقت التعديل) ثم يُتجاهل.
- عمر الجلسة يُحسب من أول سطر في السجل، فالجلسة المستأنفة أو المضغوطة تحتفظ بعمرها الأصلي. للتخفيف: العمر وحده لا يُفعّل المستوى القوي ما دام السياق أقل من 30 ألف توكن.

## متغيرات البيئة (للاختبار)

`CONTEXT_GUARD_SOFT` و`CONTEXT_GUARD_STRONG` و`CONTEXT_GUARD_BLOCK` (توكن)، `CONTEXT_GUARD_AGE_SOFT` و`CONTEXT_GUARD_AGE_STRONG` (ساعات). تغلب الملفات وتخضع لنفس الحدود الدنيا؛ القيم غير الصالحة تُتجاهل.

## الخصوصية والحدود

- يقرأ فقط مسار السجل الذي يعطيه Claude Code للهوك (آخر ~400 كيلوبايت وأول سطر؛ وإذا ما لقي سجل usage هناك يقرأ للخلف حتى 8 ميجابايت) وملفات الإعداد أعلاه.
- يكتب فقط ملف عدّاد صغير في مجلد temp (`ctxguard_<session>.txt`).
- حجم السياق يُؤخذ من آخر سجل `usage` (إدخال + قراءة كاش + إنشاء كاش)؛ تقدير وليس بيانات فوترة.
